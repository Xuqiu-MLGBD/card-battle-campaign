# 关卡挑战版 · 沙盒卡交付说明（MMD 沙盒模式 / chatVersion:1）

> 这一份是**给装卡的人看的**。打包脚本：`开源卡牌案例/建沙盒卡.py`；
> 产物：`开源卡牌案例/输出/关卡挑战版-沙盒卡.json`（六键导入 JSON）。

## 一、装卡三步（**第 ② 步漏了就白装**）

1. **新建一张卡**（编辑页导入按新卡处理）。
2. **首次保存之前**，在创卡页把「新版聊天页」选成 **使用新版** —— 这个选择**首次保存后永久不可改**。
   漏了这一步，卡能进，但 `sdk.*` / 舞台全不在，页面**没有任何报错**（只是永远不出现）。
3. 创卡页「**导入正则**」选 `输出/关卡挑战版-沙盒卡.json`（六键格式）。
   人设另见 `输出/人设-卡牌对战.txt`，**手工粘贴**进人设框（导入页不读 `personality` 字段）。

## 二、装完怎么玩

- 装上卡后**首屏自动打开舞台**（整屏 · `full` 模式），看到的是**我们自己的主页面**：
  **卡牌图鉴 / 开始游戏 / 更多内容**。
- 开始游戏 → **挑战关**（五关，格数逐关 +1：第一关双方各 1 格 … 第五关 5 格，按进度解锁）
  或 **自由关**（双方各 1 / 3 / 5 格）。
- 换关卡是**页内重开**（不出卡、不重载页面）；右上角有「**返回原生界面**」可以退回聊天页。
- 进度存在 `localStorage`（沙盒里按卡隔离、刷新不丢），并且会镜像一份到 `sdk.save`（跨设备用）。

"我这边测新代码、那边跑旧卡"能拖很久（实测被这件事误导过一次：报告里的自检条数是旧版的）。

## 四、验收状态（2026-10-03 晚 修一轮）

**⭐ 这一轮修掉的是最关键的一条：真机上"怎么是旧页面"**。
根因：沙盒是**装卡时整卡抽取、页面加载完之后才执行脚本**，于是 `外壳.js` 执行时排在他后面的
`卡库.js` 还没加载 → `CAMPAIGN_DATA` 还是 undefined → 引导直接 return（主页面不建、
上游那个 Play / Tutorial / How To Play 菜单也不隐藏）。而**本地预览看不出这个问题** ——
`build-preview.py` 是把卡的内容在 DOMContentLoaded 之前装好的，时序不一样。
修法：① `外壳.js` 的引导会**重试**（等 `CAMPAIGN_DATA` 出现，最多约 4 秒，有一次性闸）；
② 适配层在挂载时**显式叫一次** `CAMPAIGN_BOOT()`，并在加载后兜底重试。

为了能验出这类问题，新增了**时序夹具** `工作-沙盒卡/做时序仿真.py` →
`仿真-装卡后注入.html`：它**在 `load` 事件之后**才按顺序注入各条规则（复刻真机时序）。
它对"装完那一刻"的判定正好复现了用户截图（主页面没有 ✗、上游菜单还没隐藏 ✗），
而重试生效后主页面出现、上游菜单隐藏 ✓。

**时序夹具里的验收**（页面加载完之后才装卡）：

- 我们的主页面（卡牌图鉴 / 开始游戏 / 更多内容）建起来了 ✓ 上游 Play/Tutorial 菜单隐藏 ✓
- `#game` 1208px ✓ 格位 150×124（屏上 159×131）✓ 变量 `--hs-stage-w/--hs-slot-w/--hs-row-w` 全部解析 ✓
- 点「开始游戏 → 自由关 3 格」→ 页内重开：格数 3 ✓ 手牌 3 ✓ 法力 1/1 ✓ 对手名「自由对练 · 3 格」✓
  **没有导航**（页面还在）✓
- **真的出了一张牌**：Voodoo Doctor 落场、手牌 3→2、法力 1→0 ✓
- 点「结束回合」→ 敌方出 Skeleton、我方回到 2/2 ✓（完整一回合）
- 页面自检 **28 通过 / 1 失败**

**⭐ 再修一轮：真机上"实际无手牌"**（用户截图：战场与手牌全空）。
根因不是没发牌 —— **牌一直在 DOM 里、数量也对，是被我们自己的「开始游戏」面板盖住了**：
面板（`.hsp-panel`）挂在 `document.body` 上、`z-index 9991`，独立网页那条路换关会整页重载、
面板随刷新消失；而沙盒里换关是**页内重开**，面板一直开着 ✗。实测判定：手牌第一张的
`elementFromPoint` 命中 `hsp-panel` 而不是 `card`。
修法：`沙盒.js` 的页内重开**先关掉我们自己的模态面板**（主页面 / 图鉴 / 开始游戏 / 关卡浮层）。
修完实测：手牌命中 `card` ✓ 出牌成功（Voodoo Doctor 落场、手牌 3→2）✓ 自检 28 通过。

**⭐ 再修一轮：真机上"卡死了"**（用户截图：棋盘手牌都正常显示，但点什么都没反应）。
根因：上游那个「ENEMY TURN」指示条 `#computerTurn` **盖住了结束回合按钮** ——
实测 END TURN 按钮中心命中的元素是 `#computerTurn` 而不是 `#endturn`：页内重开之后它还留着
`display:block`（独立网页那条路靠整页重载清掉它）。真实点击全落在它身上，于是"卡死"。
（又一次"合成事件绕过命中测试"的假阴性 —— 我的自动化点击是直接派发到按钮上的，看不出被盖。）
修法两处：① `样式.css` 给 `#computerTurn`（以及双方对话气泡）加 `pointer-events:none`
—— **指示条永远不许吃点击**，回合期间禁点由我们自己的演出锁负责；
② `沙盒.js` 的页内重开把 `#computerTurn` 复位成 `display:none`。
修完实测：**命中 `endturn`** ✓ 点一下回合推进（法力 1/1 → **2/2**）✓ 敌方出牌 ✓ 锁正常释放 ✓。

**⭐ 再修一轮：真机上"我的回合为什么会有遮罩"**（用户截图：我方回合、法力 4/4，手牌区被压暗）。
那是**我们自己的渐变蒙版**（`#hs-mask`，拖牌/瞄准时"压暗没在指的那半张战场"）。
它原本只在"敌方回合那段演出播完"的链条末尾撤掉 —— 那条链只要没走到头（演出被打断、页内重开、
异常），蒙版就一直挂在我方回合上 ✗；另外页内重开也没清上一局的临时图层。
修法两条：① **立一条硬不变式**：`界面.js` 的回合开始那一拍**先撤一次遮罩**
（"我方回合 = 没有遮罩"是回合的语义，不该依赖演出收尾）；② 页内重开的**收尾**再清一遍
临时图层（蒙版 / 箭头 / 预览 / 提示条 / 结算条 / 飘字层），并显式放弃上一局挂着的待选。
逐拍实测：开局 `mask=ok` ✓ → **拖拽中 mask/arrow/preview 三个同时 ON**（这是该亮的）✓ →
出牌后全部 `ok` ✓ → 回到我方 `mask=ok` ✓ 法力 2/2 ✓。

**⚠ 还没修好的两条（都是观感，不影响规则）**：

1. 血量的那条自检 ⑨ 红：**`.playerHeroHealth` 这个元素在沙盒里似乎没生成**（`querySelector` 取不到，
   而 `.playerhero` 取得到；骨架字符串里明明有它）→ 表现应该是英雄框里不显示血量数字。
   下一步：查上游 `elementsController.js` 建这个元素的那两行（它按 `#contents` 找父节点，
   沙盒里父节点在我们的根节点内，可能条件没满足）与骨架注入后的实际 DOM。
2. 沙盒里缺 `?v=` 版本号、箭头不在 body 直接子节点 —— 这两条本来就是"独立网页口径"，
   自检已按沙盒跳过（不是缺陷）。

**一次教训（值得记）**：**本地仿真 ≠ 真机**，差别恰恰在"什么时候跑脚本"。凡是依赖

## 实机"没有手牌 + 英雄框没有血量数字"的追查与修法（2026-10-04）

实机截图给出的关键线索：**关卡信息都对**（第一关 1 格、对手「学徒 · 血牙」、法力 1/1），
但**英雄框里没有血量数字**，而且**手牌是空的** —— 这两件事**同源**：

> 上游的发牌函数 `startGame()` 第一件事就是读 `.opposingHeroHealth` 判"是不是教程"
> （`index.js:96`，写的是 `document.querySelector('.opposingHeroHealth').innerText`）。
> **元素不存在时它直接抛错**，抛错点之后的整段（**发牌**）就不再执行 ——
> 于是"没有血量数字"和"没有手牌"一起出现。

**三处修补**（都在 `游戏/沙盒.js` 与 `游戏/卡库.js`）：

1. **进卡时先把血量元素补齐**（`确保血量元素()`，在 index.js 之前跑）：有就用、没有就按上游结构
   补一个进 `.playerhero` / `.opponenthero`；写值一律用 **`textContent`**（不再用 `innerText`
   —— 它是渲染相关属性，对"还没布局/隐藏"的元素写进去未必留得住）。
2. **开局收尾再保证一次**：实测开局那串动作里**有人把这两个元素从 DOM 里弄掉了**
   （开局前「30」还在，开完一局 `querySelector` 就取不到）—— 所以收尾时"缺了就补、有就写值"。
3. **兜底发牌**（`兜底发牌()`）：上游那条发牌路要是没把牌发出来（异常/规则不匹配），
   我们自己从 `playerDeck` 抽三张按卡面工厂发进手牌 —— **手上没牌 = 玩家什么都做不了**，
   宁可兜底也不能开局是空的。

**时序夹具实测**：血量元素「30」`block/visible/33x30` ✓、手牌 3 ✓、格数 3 ✓、
两步点选出牌 ✓（提示条 → Voodoo Doctor 落场、手牌 3→2）✓、**页面自检 28 通过 / 0 失败** ✓
（⑨ 这条从"一直红"变成了绿）。

**未验**：真实平台（`meimoai15.com`）。这三处修补是**对着实机症状的因果链**下的，但只有导入实机才算数。



## 六、出牌的两条路（2026-10-04 重做：用户"导出后手牌用不了"）

用户原话：「我觉得应该是转为 mmd 格式的过程中出现了问题，需要检索全代码，重新设计」。
这个判断是对的 —— 问题不在"转格式"，而在**出牌这条路依赖了太多"独立网页里才成立"的东西**。

**审计：出牌路径的全部外部依赖**

| 依赖 | 独立网页 | 装进沙盒舞台 |
|---|---|---|
| 精确落点坐标（`slotAt(clientX, clientY)`） | 对得上 | 对得上，但舞台缩放/宿主容器一变就脆 |
| 舞台缩放换算（`toDesign`，除以 `#game` 的 scale） | 对得上 | 依赖 `#game` 的 rect，宿主样式一动就偏 |
| 只挂在 `mousedown/mousemove/mouseup` 上的处理器 | 正常 | 触摸设备 / 宿主拦截时可能收不到 |
| 上游全局量（`playerCardSlot2` / `originalDeck` / `collision` / `getNameOfElement`） | 正常 | 正常（都已验） |

**重做成两条互相独立的路**（任一条通就能玩）：

1. **拖拽**（原有）：拖手牌 → 悬停高亮格子 → 松手落子。
2. **点选（新增）**：**点一下手牌** → 两排格位点亮 + 提示「点一个空格子，把它放上去（Esc 取消）」
   → **点一个空格子** → 出牌。这条路只用"点在哪一格"这一个几何判断，不依赖落点精度、不依赖缩放换算，
   鼠标 / 触摸 / 笔一样。

"这是一次点、还是一次拖"也**不用位移阈值**：松手时指针**还在那张牌上**（`elementFromPoint` 命中它）→ 当点；
否则当拖。缩放、触摸、别人家的页面里都成立。

**实测（时序夹具，页面加载完之后才装卡）**：点手牌 → 提示条 + **3 个空格子全部点亮** ✓ →
点空格子 → **Elven Archer 落场、手牌 3→2、法力 1→0** ✓；拖拽那条路回归 → 拖到**第 2 格**落子
（`dataset.slot = "1"`，0 基）✓ 手牌 3→2 ✓；两条路之后页面自检都是 27 通过 / 1 失败（只剩 ⑨）。
