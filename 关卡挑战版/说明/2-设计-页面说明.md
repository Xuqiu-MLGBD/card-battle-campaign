# 对战页面 · 设计说明（每一处的思路与要求）

> 这份文档回答一件事：**这个对战页面为什么长成现在这样。**
> 每一节都写清三件事：它是什么、**为什么这么做**（多数直接来自用户的原话）、以及它的验收方式。
> 与实现细节对应的清单在 `变更清单.md`（谈定即入册）与 `动画管线清单.md`（待做全量）。

---

## 一、舞台：固定比例的设计画布

**是什么**：整个游戏界面装进一个 `#game`，设计尺寸 **1208 × 自适应高度**，整块被 `transform: scale(k)` 缩放居中。

**为什么**：
- 用户要「整个游戏界面做进一个窗体里，随浏览器窗口保持一个固定的比例进行缩放」——所以钉一个设计画布，里面所有坐标都变成**设计坐标**，元素之间的大小与位置关系被整体锁死；
- 宽度定死 1208（= 右栏左缘 1000 + 右栏 200 + 8 右边距），**高度不是常数**：按窗口宽高比算出"这一刻舞台该多高"，回填到 `--hs-stage-h`。这样窗口多出来的高度变成两排之间可伸缩的对峙区，**而不是上下留黑边**（用户反馈过「两边的留边太多」）。

**验收**：自检 ①；设计高度夹在 [520, 1600]。

## 二、两个视角：平铺 / 斜向立体

**是什么**：右栏「视角」按钮切换（快捷键 `V`，选择记在 `localStorage`，`?view=tilt` 可直接开）。立体视角下战场 `rotateX(54°)` + `perspective 1100px`，近大远小；场上卡变成「桌上一块板 + 板上立着一张小牌」；敌方英雄连同名字、血量、被打星星一起搬到**桌子对面**。

**为什么**：
- 用户拿一个 three.js 的参考文件要求「给战场设置两个视角」；但**没有引入 three.js**——见 §3.7：它压缩后约 600KB，而这份成品要压进 MMD 卡（每条正则 ≤18000 UTF-16），光它就多出三十几条规则；且我们整套命中/拖放都是基于 DOM 的，换 WebGL 等于全部重写。CSS 3D 能让浏览器**按真实投影**做命中测试，两全。
- **只倾斜战场**：手牌、法力条、右栏、预览、箭头、蒙版全部留在屏幕坐标系——参考图里就是这样（桌面往后倒，UI 还是正对的）。
- **桌布是纯色**：用户说「桌上的方格纹理就别加了，只保留纯色桌布」。

**验收**：自检 ②③④⑮⑯；两视图的槽矩形都不重叠（命中判定依赖它）。

## 三、右栏（自上而下五段）

| 段 | 内容 | 为什么 |
|---|---|---|
| 顶部 | 「设置」「平铺/立体视角」并排 | 用户要求把头像移走、腾出中央空间；这两颗是全局开关，固定在右上 |
| 敌将 | 敌方英雄框（名字 + 血量） | 用户要「双方头像移到回合结束按键的上下方」 |
| 中 | **END TURN** | 夹在两个英雄之间，是每回合唯一的常驻动作键 |
| 我将 | 我方英雄框（名字 + 血量） | 同上；血量必须**贴在框内下沿上方**（用户报过「被任务区挡住」） |
| 底部 | 任务区（预留） | 占位，留给后续内容；它曾经压住我方血量，所以血量上移了 |

**名字标签**：`#playerlabel` / `#opponentlabel` 被搬进各自英雄框当标题。二者**必须分开写位置**——立体视角下敌将搬到桌对面，名字要跟着走（用户报过「敌方的名字位置记得要改」，截图里它压在了设置/视角按钮上）。

**英雄框去椭圆**：上游内层是 `.cardinplay`（`border-radius:100%`），圆角必须压在内层上才有效——第一版给外层写，里层椭圆原样留着。

**验收**：自检 ⑧⑨。

## 四、左栏：法力竖列

**是什么**：屏幕左侧一条竖管，水晶从**底部往上**堆；上方是「n/m」数值。

**为什么**：用户要「法力水晶做成屏幕左侧一个竖直的系统」，并且「下方和战场下方对齐」。上游原本是横排底槽——改竖排时我把它的底色与描边一起拆了，导致「看不见」；用户驳回了我"颜色接近"的解释，查明真因是**注释嵌套把整条规则吃掉了** + 上游两条 12% 宽的黑色侧边条（`z-index` 十一位）盖在上面。现在恢复了上游的青色底 + 亮青描边。

**验收**：自检 ⑫ 之外由 `fitStage` 保证底边与「我方部署位那一排」底边对齐。

## 五、战场：两排部署位（格数由关卡决定）

**是什么**：每侧一排虚线部署位；格子宽 150、**宽高比 251:207**（高 124），一排总宽固定 888（两侧各留 27px），**格子在这条带子里居中**。

**几格**：**由本局决定**（用户 2026-10-03）：挑战关按关卡表的 `slots` —— 第一关双方各 1 格、第二关 2 格……第五关 5 格；自由关由 `?free=1|3|5` 给档位。这件事只有一个来源：`卡库.js` 乙段算出的 `HS_SLOTS`，界面（`SLOT_COUNT`）与引擎（`状态.场上上限`）都读它。所以 1 格那关就一个格子落在正中，5 格时与从前的观感一样。

**为什么**：
- 用户要求「布局区上的角色槽大概要改成是 251：207 的宽高比」——上一版格子高度跟着舞台高度走，窗口一矮就被压成将近正方形（实测 150×153），形状会漂；
- 格子是**有编号的实体**（第 1–N 格），不只是装饰：落格判定"拖到第几格就落在第几格"，且将来场地卡挂在**格**上而不是角色上；卡片定位量的是真实 `offsetLeft`（`cellLeft()`），所以格数怎么变都不会落偏。

**命中判定**：一律**按矩形的几何判定**，不用 `elementFromPoint`——后者只看最上面那一个元素，页面上任何全屏覆盖（上游的载入层 `#load` 就是全屏 + `z-index:1000000`）都会让它永久落空。立体视角下量的是投影后的矩形，实测 5 个格子的矩形互不重叠，所以几何判定照样成立。

**验收**：自检 ⑤（格数 = 本局部署位）⑥（宽高比）⑦（相邻不重叠，两格以上才判）。

## 六、手牌区与拖牌

**是什么**：底部一排手牌；按住一张往场上拖，画一条绿箭头（手牌原位置 → 指针），落点格子高亮，松手即结算。

**为什么**：
- **卡片不跟指针跑**：上游那套"把卡片挪到指针下"用的是视口坐标，舞台一缩放就错位，而且卡片太大挡死场地。用户要的是"拖到对应位置让它进入对应位置"——所以拖动期间卡片留在手牌里原地不动，只压暗表示被拿起，内容交给预览面板；
- **箭头画在屏幕坐标系**、挂在 `body` 上：立体视角下设计坐标到屏幕不再是线性映射，按设计坐标画的箭头会指不到指针底下；
- **落格坐标用 `offsetLeft`**（布局值）而不是 `getBoundingClientRect`（投影值）——同样的原因，否则卡片会一格一格往里挤。

**验收**：自检 ⑪；实测「第 2 格的箭头终点 = 该格中心，偏差 0」。

## 七、预览面板（同一个面板，两种用法）

| 什么时候 | 显示什么 |
|---|---|
| 拖手牌时 | 名字 / 费用 / 攻血 / 效果文案（手牌 DOM 是完整卡面） |
| 悬停场上卡牌或英雄时 | 名字 / 攻血（场上卡 DOM 只剩攻血两个数字，名字由我们记账） |

**硬规则：面板永远在指针的对面那一侧**（鼠标在左 → 面板在右，反之亦然，**两者不得同侧**）。用户明确指出这是"根本设计"，我曾只在悬停路径上实现、瞄准时忘了换边，被驳回。

**另两条**：面板必须盖在 END TURN 之上（上游会把那颗按钮的行内 `z-index` 抬到 50，面板是 200）；场上卡的名字只能自己记——我方的用出牌前设过的 `getNameOfElement`，敌方的用**牌堆/手牌差集**。

**验收**：自检 ⑬⑭。

## 八、蒙版（压暗没在指/不能操作的那半边）

**是什么**：一块 `pointer-events:none` 的渐变遮罩。
- 拖手牌/单位瞄准时：压暗**没在指的那半张战场**；
- **敌方回合时：压暗下半张（我方那半边）**，回合结束撤掉——用来说明"这一段你不能操作"。

**为什么**：用户要"拖出手牌区就显示箭头 + 预览"，而遮罩是为了让"正在指的那半边"凸显出来；敌方回合那半张遮罩是用户 2026-10-03 的新要求，比"按钮变灰"更能说清状态。
⚠ 实现细节：`applyMask(ny)` 按 `ny < 0.5` 判断"指针在上半 → 盖下半"，所以要盖下半必须传 **0.1**（我写过 0.9，结果盖了上半）。

**验收**：自检 ⑰⑱。

## 九、箭头的三套

| 用途 | 在哪 | 备注 |
|---|---|---|
| 上游那条红色虚线（单位瞄准） | `#svg`（固定定位、视口坐标） | 保留原样呈现 |
| 我们给它补的箭头尖 | `#hs-arrowhead`（同一个 svg 里的 polygon） | 上游的尖原本是光标图，随美术剥离删掉了；并且**把虚线收短到三角根部**，否则虚线从三角两侧穿出来 |
| 手牌拖拽的绿箭头 | `#hs-arrow` | 也挂在 `body` 上、视口坐标；线宽与箭头按舞台缩放乘 k |

**验收**：自检 ⑪⑫。攻击演出另外由管线画箭头（见下）。

## 十、演出层与管线（`演出.js`）

**是什么**：一把带 reason 的锁 + 串行队列 + 六个原语（箭头/运卡/冲刺/飘字/击中玩家/退场）+ 配方表（attack / deploy / draw / turn / gain / heal）+ 「所有演出播完」的确切时点 `whenIdle()`。

**核心原则**（用户反复强调、也是那篇 Phaser 文章与三国杀架构文的同一句）：
> **先定下这一回合要做什么（只看不碰）→ 队列按序播 → 每一条在它自己的那一拍才施加变更。**
> 打中那一拍才扣血、箭头拉到那一刻那张牌才浮现、牌飞进手牌那一刻它才真的进手牌区。
> 全部播完（`whenIdle`）才把回合交出去。

**其余配套**：演出期间锁输入（在 `document` **捕获阶段**吃掉 mousedown，所以上游绑在元素上的处理器也进不来）；内部补发的事件（"打中"那一拍）带 `__hsStrike` 标记放行；段末看门狗（页面被节流时完成信号可能永不到来，到点跳到终态）；失焦/可见性变化自动跳到终态；可跳过（Esc/右键）；倍速只改演出时长、**结算一点不动**。

**验收**：自检 ⑲⑳；实测时间线 + 逐帧采样（见 §四.12 与当轮实测记录）。

## 十一、END TURN 按钮的两态

**规则**（用户原话）：
> 只要敌方的行动动画不在播放，那就是我的回合，那就要是一直绿的。我按下之后，它就变成灰的，直到对方的所有动画管线播放完毕，然后我可以行动了，就切换成绿色提醒我，是我的回合了。

所以只有两态，判据是"**敌方是否在行动**"（`enemyBusy`），**不看锁**（我方自己的演出期间它照样是绿的）：
- 敌方在行动（含它的全部演出）→ 灰 + `ENEMY TURN`；
- 否则 → 绿 + `END TURN`。

**同一时刻**还要做三件事：撤掉下半遮罩、提示「敌方回合结束」、交回合给玩家。

**验收**：逐帧采样（变绿那一拍已经不在敌方演出中；结束态 = 绿 + 队列空闲 + 遮罩已撤）。

## 十二、卡面与信息

- **卡图全部移除**（上游 128 个美术文件 / 71.2MB 全剥净），留素面框 + 数值；场上卡的 DOM 里**只剩攻血两个数字**——所以悬停预览的名字必须由我们记账；
- **攻血徽章**：上游用**百分比外边距**定位（93%×卡宽），卡片一改成横向比例就飞出卡外。现在改成 `left/right/bottom` 百分比 + `translate(-50%,-50%)` 居中，与卡片比例无关；
- **命中框**：英雄框是矩形（去椭圆），场上卡是圆角框；悬停高亮由我们加绿环（上游显式关掉了英雄的 hover 光）；
- **血量数字**：贴在英雄框内沿上方 40px（否则掉到框外被任务区压住）；
- **关键词角标**：角标图随美术剥离删了 → 用**类名 + 纯色**画（嘲讽「嘲」圆牌、神圣护盾金环）；冻结/沉默要等效果表；
- **退场**：上游是一句 `remove()`（没有过程）→ 我们旁听 `remove`，克隆一份回原位演退场；**真正的移除照旧立刻发生**，规则不受影响。

## 十三、色彩与字体

深色简洁窗体：底色 `--hs-bg`、面板 `--hs-panel`、分隔 `--hs-line`、强调 `--hs-accent`、高亮绿 `--hs-ok`、危险红 `--hs-danger`；字体是一串**系统字体**（上游的 Belwe 是暴雪商用字体，必须换掉）。左栏法力管保留上游的青色底 + 亮青描边（用户要求"原本看得一清二楚"的观感）。

---

## 十四、不变量（改动时不许破坏）

1. 预览面板永远与指针异侧；
2. END TURN 两态只由"敌方是否在行动"决定；
3. 演出期间不响应操作（锁在捕获阶段吃事件），但内部补发的事件必须放行；
4. 结算绝不先于动画（先规划、边演边施加、播完才交回合）；
5. 上游代码**一字未改**（全部靠包装/旁听/拦截）；
6. 凡是"我们主动制造的事件"必须能被识别出来（`__hsStrike`）；
7. 凡是 `catch` 至少留一行输出（静默失败已坑过三次）。

## 十五、怎么验

```bash
python 工具/组装.py            # 组装 + 构建期检查（上游未改 / 美术剥净 / CSS 静默失效 / 版本号）
node test_levels.mjs      # 195 项
node test_campaign.mjs    #  95 项
# 浏览器控制台：
HS_INTERACT.check()       # 22 条运行时自检 → { 通过, 失败, 总数, 就绪 }
HS_PIPELINE.log()         # 最近播过的动作（含标签与时间）
HS_PIPELINE.dump()        # 时间线文本
HS_PIPELINE.lastStrike()  # 最近一次攻击"有没有落地"、有没有抛错
```

**每次构建后跑一遍自检**；红了对照 `变更清单.md` 把对应那条重新落实，**不许只修表面**。
