# 全链路检错（2026-10-04）

> 你给的那张图：每层出错 → **层 + 错误码 + 上下文 + 处理** → **错误聚合器** → **诊断报告** →
> **可恢复？** 可恢复就"回到安全节点继续"，不可恢复就"暂停游戏并提示用户"。
> 这一份记我们**实际落了哪些、哪些还不能落、为什么**，以及四道闸分别在哪跑。

## 一、图上的八层 ↔ 我们的模块

| 图的层 | 图里的码 | 我们这边 | 状态 |
|---|---|---|---|
| 0 输入层 | `UI_INVALID_INPUT` | 拖拽/点选入口（`界面.js onDown/onUp`）+ 两条出牌路 | ✅ 有码位；命中测试类问题用 `elementFromPoint` 断言 |
| 1 意图层 | `META_INCOMPLETE` | `playFromHand` / `应用一次攻击` 的入参检查 | ✅ **已接**（卡认不出/取不到牌库 → 报 + 给玩家一句人话） |
| 2 规则核心 | `RuleError`（`NOT_YOUR_TURN` / `STACK_NOT_EMPTY` / `INVALID_TARGET` / `INSUFFICIENT_MANA`…） | `引擎.js` 的 **27 条码表** + `否(原因, 上下文)` | ✅ **已接**（改进 A；日志/UI 都拿码） |
| 3 决策层 | `DECISION_MALFORMED` / `DECISION_INVALID` | `发起决策(请求)` 单一出口 + `决策.js 选目标` | ✅ 出口已有（改进 D）；`DECISION_INVALID` **只记录不提示**（点是禁止刷屏的用户噪声） |
| 4 提交层 | `ATOMIC_VIOLATION` / `REVISION_GAP` | `事件.js 变更/应用/校验` + 引擎 `回放` | ⚠️ **能力已有、暂未挂到运行期**（要先有"权威状态 + revision"，即改进 B） |
| 5 事件层 | `EVENT_STATE_MISMATCH` | `事件.js 校验事件`（事件↔状态互为因果） | ⚠️ 同上（引擎里有，页面还没有事件流） |
| 6 展示层 | `PRESENTATION_AHEAD` / `ANIM_WRITE_STATE` / `UI_WRONG_SOURCE` | `演出.js` 管线（锁+队列+skip）、`界面.js` 渲染 | ✅ 已落三条**同族的**：`PRESENTATION_LEFTOVER`（残留蒙版/箭头/预览）、`UI_MODAL_OVER_GAME`（面板压场）、`ANIM_LOCK_STUCK`（锁没释放）、`UI_CAP_MISMATCH`（水晶颗数≠上限） |
| 7 日志与回放 | `LOG_INCOMPLETE` | `事件.js` 顺序号/因果链 + `引擎.js 回放` + 标准对局基线 | ⚠️ node 侧已验；运行期待 B |
| 8 适配/宿主（我们加的） | `SKELETON_INCOMPLETE` / `MODULE_MISSING` | `沙盒.js` 的骨架注入与模块到齐检查 | ✅ 已接（← 真案例：实机"没有手牌/没有血量数字"就是这一类） |

**结论**：图的"零件"我们**九成都有**（码表、聚合、报告、恢复钩子、回放、事件校验），
差的是**把 4/5/6/7 的那几条挂到运行期** —— 而它们全都依赖同一件事：**权威状态 + revision**（改进 B）。
所以检错层是"和 B 一起完工"的：这一轮把**不依赖 B 的部分先落满**。

## 二、这一轮实际落了什么

新文件 **`游戏/检错.js`**：

- `报(层, 码, 上下文, 严重)` —— **所有层只调这一个入口**，于是"哪里出过什么事"永远只有一份账；
  严重度三档：`提示`（只记录，不打扰玩家）/ `严重`（**回到安全节点**）/ `致命`（**暂停游戏并提示用户**）。
- `登记恢复(码, fn)` / `登记暂停(fn)` —— 界面在 `buildChrome()` 里登记**恢复动作**
  （撤临时图层 / 关面板 / `pipeline.skip()` 跳到终态 / 重画水晶），以及致命时的暂停条
  （复用失败条那套观感，带一个「导出本局信息」按钮）。
- **两种恢复策略**（区别在安不安全）：`PRESENTATION_LEFTOVER / UI_MODAL_OVER_GAME / UI_CAP_MISMATCH / UI_WRONG_SOURCE`
  属**安全清单**，查到就**立刻**修；其余（如"锁卡住"会跳过演出）**连续两次**才升级并恢复。
- `跑不变量()` —— 把这一周踩过的坑**逐条变成断言**（只读，不修）：残留临时图层、模态压场、
  锁没释放、水晶颗数与上限不符、影子引擎状态不自洽、事件校验、沙盒骨架/血量元素/模块到齐。
- `报告()` —— 人看的诊断文本（按码计数 + 最近 20 条 + 运行期不变量结果），进「导出本局信息」。

**机器检查**：页面自检新增 **㉝** 两条（检错层在位 / **空闲态运行期不变量全过**）。

## 三、实测（`?level=1`）

| 步骤 | 结果 |
|---|---|
| 空闲态跑不变量 | **[] 全过** |
| 故意留一块蒙版（`#hs-mask.classList.add('on')`） | 抓到 **`展示层/PRESENTATION_LEFTOVER`** ✓ |
| 体检 → 安全清单 → 立刻恢复 | 蒙版被撤掉 ✓，再跑不变量 **[]** ✓ |
| 页面自检 | **37/37**（35 → 37） |

**它当场还抓到了自己的一条错**：第一版 `跑不变量()` 把 `引擎.新建()` 的返回值（那是个**包**
`{状态, 事件, 变更, 待选择}`）直接当状态传给 `检查()` → 报 `Cannot read properties of undefined (reading 'p0')`。
—— 这正是检错层该有的样子：**连"检错器自己写错"都会被记成一条带层带码的记录**，而不是静静失败。

## 四、四道闸（同一个检错层的四个时间点）

| 闸 | 在哪跑 | 查什么 |
|---|---|---|
| **构建期** | `工具/组装.py` | 上游一字未改 / 补丁锚点 / 纯逻辑硬约束（引擎不许碰 document）/ CSS 嵌套注释与未定义变量 / 模块清单与顺序 |
| **装载期** | `游戏/沙盒.js`（进卡那一刻） | 骨架完整性（`#contents`/`#game`/`#cards`…）、血量元素补齐、模块到齐、三道防线（拦 alert/重载/投降） |
| **运行期** | `HS_CHECK.跑不变量()` | 上面那张表（残留图层 / 模态 / 锁 / 水晶 / 骨架 / 引擎自洽 / 事件校验） |
| **回归期** | 四套 node 断言 + 页面自检 + 时序夹具 | 507 项断言、37 项目检、以及"页面加载完之后才装卡"的时序夹具 |

## 五、还欠的（都与改进 B/C 绑在一起）

1. `ATOMIC_VIOLATION`（变更重放 ≠ 提交状态）—— 引擎里已有 `回放` 与末态哈希，挂到运行期要有权威状态。
2. `REVISION_GAP`（revision 连续）—— 要先有 revision。
3. `PRESENTATION_AHEAD`（展示不得超前于权威）—— 要有"权威状态"才能比。
4. `ANIM_WRITE_STATE`（动画层越权写状态）—— 先把"写状态"收成单一入口（改进 C），
   才谈得上"拦越权"；现在是源级检查（`演出.js` 里不出现写血/写攻）可以先加。
5. `LOG_INCOMPLETE`（可回放性）—— node 侧已验（标准对局基线），运行期等 B。
