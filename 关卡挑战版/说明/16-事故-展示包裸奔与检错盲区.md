# 16 · 事故复盘：展示包"裸 HTML"与检错层的盲区

> 2026-10-04。这一篇是**一次真实事故**的完整记录：用户打开展示包看到的是没上样式的裸页面
> （Victory / Sound / Options / Show FPS 全暴露在明面上），而**页面自检当时 35 项全绿**。
> 顺手在查证过程中又抓到状态层一个真缺陷。两件事都写在这里，因为是同一个教训的两面：
> **检错层没覆盖到的地方，就是"看起来一切正常"的地方。**

---

## 一、现象与第一反应（别急着怪打包脚本）

用户截图：包里的 `index.html` 打开后，没有样式、所有隐藏页面外露。
第一反应是"样式的路径写错了" —— 但**同一个 index.html 在工程里是好的**，所以只能是"包里少了东西"。

一行命令就把它钉住了（`工具/引用体检.js`，不跑浏览器）：

```
[引用] 展示-关卡挑战版 ✗ 扫了 17 条，必须存在的缺 4 条：
  · styles.css                —— 被 index.html 引用
  · index.js                  —— 被 index.html 引用
  · src/scripts/attack.js     —— 被 index.html 引用
  · src/scripts/elementsController.js —— 被 index.html 引用
```

四个文件都在包里，只是在**子目录** `上游运行时/` 里 —— 而 `index.html` 是按**根路径**引用它们的。
少一张 `styles.css` 就是"裸 HTML"：上游那套靠样式表隐藏整页容器的规则全部失效。

## 二、根因（两层，第二层比第一层严重）

1. **打包器用白名单 + 搬家**。旧版 `打包展示.py` 手写一张"要拷哪些文件"的清单，并把仍随包分发的
   第三方文件统一塞进 `上游运行时/`。**搬家那一刻引用就断了**。
2. **没有任何一道检查在看"文件在不在"**。页面自检 35 项全绿 —— 因为它只查运行时状态
   （水晶颗数、锁、对账、模块全局量），从来没人问过"页面引用的东西都加载成功了吗"。
   这是**盲区**，不是"检查写错了"。

## 三、修法与新增的三道闸门

**打包改成"整树复制 + 只在包内另放附加件"**（`打包展示.py`）：
工程里有什么就原样复制什么，**只允许排除工作目录，不允许搬家**。
第三方文件留在被引用的位置（`styles.css` / `index.js` / `src/scripts/*.js`），
许可证与署名 README 另放 `来源与许可/`（MIT 要求随包，且不打断引用）。

三道机器闸门（任一失败就 **非零退出**，包不许发布）：

| 闸门 | 手段 | 抓什么 |
|---|---|---|
| ① 引用齐备 | `node 工具/引用体检.js <包>` | 包内每个被引用的本地文件都在它被引用的位置 |
| ② 与工程一致 | 同上 `--对比 <工程>` | 工程里能解析到的每个引用，包里也必须有 |
| ③ 第三方清单相符 | 比对包内实况 | `来源与许可.txt` 说"仅这 4 件"，就得恰好这 4 件 |

**运行期也补了两条断言**（`游戏/检错.js` → 页面自检 ㊲/㊳）：

* `ASSET_MISSING`：本地 `<link>`/`<script>` 有没有加载失败（`performance` 的 `responseStatus`、
  样式表"存在但规则为空"这两档证据）；
* `STYLE_NOT_APPLIED`：样式**是不是真的落到了元素上**。

**实测它真的会红**（这条最要紧 —— 不能只证明"修好了"，还要证明"检查有牙"）：
把包里的 `styles.css` 挪走再打开，自检立刻给出

```
㊲ 本地资源齐备 …… （缺：link styles.css（HTTP 404））
㊳ 样式真的落到元素上（不是裸 HTML）…… 外露的整页容器=optionsmenu、tutorialmenu、shopmenu、victory、howtoplay
㉝ 运行期不变量（空闲态）…… （不通过：适配/宿主/ASSET_MISSING、适配/宿主/STYLE_NOT_APPLIED）
```

—— ㊳ 那句"外露的整页容器"指认的，正是用户截图上的现象。

## 四、写检查时踩到的四个"误报坑"（记录下来，别再犯）

一个检查如果**动不动就红**，就没人看它了；所以修完"该红时会红"之后，还得修"不该红时不能红"。

| 断言 | 第一版错在哪 | 改成什么判据 |
|---|---|---|
| ㊳ 样式生效 | 拿 `body` 计算底色必须是**纯黑**（上游 `styles.css` 里那句） | **加载事实**：那张表在不在 `document.styleSheets` 里、规则是否非空。层叠本来就会覆盖上游的值 —— 我们自己的深蓝底色把这条判据误伤了 |
| ⑦ 同排格子不重叠 | 拿 `getBoundingClientRect` 比相邻格 | **布局坐标** `offsetLeft/offsetWidth`。立体视角有透视，投影后的外接矩形本来就会互相压一点（同一排实测 161/150/139/139/150），与 ⑤⑥ 是同一条坑 |
| ㉚ 关键落点没被盖 | 舞台还没显示（开场那几秒 `visibility:hidden`）时也判 | 加"舞台可见"前置条件：隐藏元素不参与命中测试，`elementFromPoint` 会一路穿透到 `body`，看着像"全被盖住" |
| ㉝/㉟ 不变量与对账 | 演出进行中也要求"干净" | 演出中只放行**展示层**的码（展示滞后是设计），引擎/事件/日志照旧红；对账的"两套真相"判据只在**空闲态**成立 |

## 五、顺带抓到的真缺陷：提交层的形状不一致

查证时打开 `HS_CHECK.报告()`，看到两条**在正常对局里**出现的 `ATOMIC_VIOLATION`
（"敌方回合结束"、"攻击结算"），而 3D 图里这条的含义是"状态与事件不一致 → 整体回滚"。
报告里只有 `{原因, revision}`，**看不出差在哪**。

做法是先让报错能诊断，再去定根因：

1. `状态.js` 的 `提交()` 每条问题改成 `{ 码, 上下文 }`，上下文里带 **差异路径**（逐路径比"重放"与"采到"）；
2. 差异立刻指认：`单位.playerCardInPlay0` —— 重放里**没有**这只随从。

根因：`求差/应用` 是按**引擎那套形状**写的（`场上` 放 id、单位字段进 `单位` 映射），
而界面交上来的是**对象数组**。于是"把变更重放回旧状态"永远不等于新状态 ——
检查没错，**是状态形状自己不自洽**（`ATOMIC_VIOLATION` 在乱报，同时"变更/事件"日志也不可回放）。

修法：**把权威状态的形状对齐引擎**（`单位` 映射 + `场上: [id]`），一处改、三处受益：

* 原子性检查从此有意义（它是真在验"施工图能否还原成品"）；
* 变更与事件可回放（原来写着"单位变化"，那个路径根本不存在）；
* **阶段 C 只剩最后一步**：把"采 + 求差"换成"直接提交变更" —— 形状已经一样了。

补的机器断言：新增第五套测试 **`test_状态.mjs`（48 项）**，只盯两件事 ——
正常一局（上台/数值变化/下场/回合推进/换序）提交后**零问题**且能重放；
真对不上时（丢信息的采集）**必须报**且上下文指出路径。两半缺一不可：
只有前半，检查是摆设；只有后半，正常对局噪声不断。

顺带修掉的两处：下场时除了抽出 id，还要**删掉 `单位` 里那份**（否则重放里留下尸体）；
"仅顺序变化"（压入/抽出表达不了）改成**整置该排**。

## 六、立成规矩（写进 README 的"六条"之外，这里是第 7、8 条）

7. **要分发的树，整树复制；只允许"排除"，不允许"搬家"。**
   凡是改了位置的，引用就会断 —— 这条比"包看起来干净"重要得多。
8. **"文件在" ≠ "生效"；判据要用"加载事实"，不要用"计算结果"。**
   另外：**检查必须既有牙（该红会红）又不无理取闹（不该红不红）**，
   所以每条断言都要写清"它在什么状态下才成立"（空闲态？演出中？舞台可见？）。

## 八、用户贴回来的那份"本局信息"：报告自己说不清

修完上面这些之后，用户又贴回一份导出 —— 它暴露的是**报告本身**的问题（这一类最耽误事：
报告是排查的入口，入口看不清，等于没有入口）：

```
自检 : {"通过":39,"失败":["㉝ …… SKELETON_INCOMPLETE"],"总数":40,"就绪":false}
脚本版本 :                     ← 整行空
回合 : playersTurn=false  锁=null  队列=0
英雄血量 : 我 ? / 敌 ?
```

三个读不出来的字段 + 一条看不懂的错。逐条查的结果：

1. **总数 40** —— 这是**上一轮构建的沙盒卡**跑出来的（本轮清单是 46/48 条）。卡里的 JS 是
   **构建时内联**的，所以"改了源码但没重建卡"就会一直是旧代码。**这是最先要排除的可能性**，
   而当时的报告里没有任何东西能说明这一点 → 于是加了"构建戳"（见下）。
2. **脚本版本整行空** —— 沙盒里没有 `<script src>`（脚本由规则注入），那一行本来就是靠
   `script[src]` 上的 `?v=` 拼出来的，自然空。**空不等于读失败**，但报告没写清原因。
3. **锁=null** —— 那句是 `String(HS_PIPELINE.reason())`，空闲时就是 `null`。
4. **英雄血量 ?** —— 只打了 `?`，看不出是"元素没建"还是"路径取错"。

### 改法

* **构建戳 `window.HS_BUILD`**：`组装.py` 把它写进 `index.html`（值就是运行时内容哈希，与 `?v=` 同源）；
  `建沙盒卡.py` 也生成一条同名模块（**直接 import 组装.py 取同一个哈希**，免得两处各算一份对不上）。
  → 从此"网页"和"沙盒"报的是同一个戳，一眼能对上"这份报告是哪次构建"。
* **新增一行"运行环境"**：独立网页/沙盒舞台 · 骨架根是谁（打 id，不打成 `[object HTMLDivElement]`）
  · 关键 id（contents/game/cards/playerhero/opposinghero）缺哪个 · 血量元素在不在 · 是否在 iframe 里。
  这一行就是为"SKELETON_INCOMPLETE 到底在说哪一层"写的。
* **脚本版本**：没有 script 标签时**明说原因**；有戳就先报戳。
* **锁**：空闲就打"空闲"，持锁打出原因（不再出现 `null`）。
* **血量**：读不到时说明是哪一步断的（`?（没有 #playerhero）` / `?（没有 .playerHeroHealth）`）。

顺手重建了沙盒卡（6 条规则 / 单条最长 98,065 UTF-16）。**并且用现成的时序夹具做了复验**：
`工作-沙盒卡/做时序仿真.py` 会生成一个"**在 load 事件之后**才按顺序注入各条规则"的页面，
复刻真机装卡时序。那份页面上：主页面建起来了 ✓ 骨架齐 ✓ 页面自检 **43/43** ✓
构建戳读到了（且与独立网页报的是**同一个值**）✓ `SKELETON_INCOMPLETE` 不再误报 ✓ 导出里如实写着
"沙盒舞台 · 骨架根=#hs-sandbox-root · 关键id齐 · 血量元素 我在 敌在"。

### 一条容易踩的体量约束

`pack_card.py` 是**按模块边界**把模块塞进规则的（塞不下就开新的一条），所以"整卡总量"不是约束，
**"单个模块"才是**：目前最大的是 `游戏/界面.js`（剥注释后约 98,065 UTF-16，单条门限 99800、
宿主硬上限 100000）。它再长就该动手拆了 —— 自检与"本局信息导出"是天然的接缝。
