## 一、先回答那个问题：脚本**装卡时跑一次**

> `<script>` 地位：**一等公民：装卡即抽出、整卡跑一次**；per-message 用 `message:mount` 事件顶替。（§ 规则能力表）

同节的三条细则，逐句都对我们有影响：

1. **抽取时机**：装卡那一刻抽出，按规则顺序收集。
2. **执行次数**：**整张卡只跑一次**（不是每条消息一次）。
   ⚠️ 但**创卡页预览会反复重跑**（每改一次规则重装一遍）→ **脚本必须幂等，自带「已初始化」哨兵**。
3. **执行机制**：内联脚本经 `(0,eval)` 执行，被包进 `(function(){…}).call(window)`；
   顶层 `var/let/const/function/class` 由编译器**显式回挂 `window`**。
   `type="module"` 被按经典脚本执行 → 里面写 `import` 必报错。
4. **错误隔离**：一段脚本报错**只废掉它自己**，后面的规则照跑；不弹窗，进调试面板。
5. **切会话**：脚本**不重跑**，但**不清除**，舞台会被平台关掉 → 属于某个会话的计数要自己在
   `conversation:switch` 里清。

> 🔴 **真红线：脚本执行时页面 DOM 还没建好。**（§2.6）—— 顶层拿 DOM 必然拿到 `null`，这是沙盒的头号坑。

> 🔴 `sdk.on` 只能写在脚本体，**绝不能写在 `message:mount` 回调里**。否则每挂一条气泡就多订一份。
> 官方校验对此有专项 WARN。（§2.2）

所以四个方向里，**"只在开局加载一次"这条是对的**（聊天页成立），而它的两个直接后果是：
初始化必须**幂等**、且必须能**等 DOM**。

## 二、四条怀疑方向，逐条对照事实

## 三、这次真机上报的那条，根因是**平台改写了查找**

文档 §2.2 / §2.3 明确写着：平台**全局改写** `Document.prototype.querySelector /
querySelectorAll / getElementById / getElementsByClassName / getElementsByTagName`：

```js
Document.prototype.querySelector = function (e) { return xc(this, e) }
Document.prototype.getElementById = function (e) { if (gc) { …mc.call(gc, `[id="…"]`)… } }
```

- 在 `message:mount` 回调里（`gc` 非 null），这些查找被**收窄到"气泡范围"**；
- `gc` 是**模块级游标**，跨 `await` / `setTimeout` 即失效；
- 而且沙盒本身是**跨源 iframe**（`c<卡片ID>.sbx.<站点>`）。

我们的牌桌在**舞台根** `#hs-sandbox-root` 里、不在气泡里 —— 用 id 去找就会拿到 `null`。
这正好解释用户报告里的那一行：

```
运行环境 : 沙盒舞台 · 骨架根=#hs-sandbox-root · 关键id缺 playerhero/opposinghero · 血量元素 我在 敌在 · 在iframe里=是
英雄血量 : 我 ?（没有 #playerhero） / 敌 ?（没有 #opposinghero）
```

**按 class 找的 `.playerHeroHealth` 在，按 id 找的 `#playerhero` 不在** —— 这就是"查找被改写"的长相。
而我们所有点击接线都按 id 找元素，于是设置/结束回合一起失灵。

### 改法：`游戏/查找.js`（独立模块）

`Element.prototype.querySelector` **没有被改写**，所以"**根部作用域**"这条路是可靠的：

1. **一律走根部作用域**：`根.querySelector(...)`；`根` = `HS_SANDBOX.根()`（独立网页则是 `body`）。
   对外导出 `HS_查找.{根,找,找id,全部}`，界面与检错层共用同一个口径（免得"界面在根里找、
   检错在 document 里找"得出两套结论）。
2. **自愈**：按结构找到后**把缺的 id 补回去**（`HS_查找.补齐()`，在引导时与每次换局前各跑一次）。
   上游 `index.js` / `attack.js` 全是按 id 找元素的 —— id 一补，它们**跟着一起恢复**，
   我们不用改上游一个字。结构锚点都来自骨架本身：
   `#cards`←`.cards`；`#playerhero`←`.playerHeroHealth` 的最近 `.cardinplay`；
   `#manacontainer`←任一 `.manabox` 的父；`#endturn`←文字是 END TURN / ENEMY TURN 的按钮。
   补的动作会以**提示级**记进检错层（看得见、不打扰）。
3. **点击留痕**：在根上挂捕获阶段的监听，只记最后 8 次点击的目标与时刻。
   读法：
   - 日志里有 `#endturn`，而"最近播过的动作"为空 → **点击接上了、后面的链没走**；
   - 日志里根本没有那个元素 → **点击没落到它身上**（多半被别的图层盖住）。
   同时记 `回合留痕`（`opponentTurn` / `playerTurn` 调用次数），与上面互为对照。

> 为什么要单独一个文件：沙盒**单条规则**有硬上限（宿主 100000 UTF-16，我们的门限 99800）。
> `界面.js` 本来就贴着门限，加上这一层后打包器**当场拒了**（实测 101571）—— 于是把这一层
> 单独成模块，`界面.js` 只留一组别名，调用点一个字都不用改。

## 七、结束回合那条"直线链"：任何一个 null 都会掐断它

用户 2026-10-04 问得很准：**结束回合的回调是先查三个节点，任意一个返回 null 就全中断，是这样吗？**
是这样。上游 `index.js` 里那段（逐字未改）：

```js
document.getElementById("endturn").addEventListener("click", function () {
  var endturn = new Audio("src/sounds/endturn.mp3"); endturn.play();
  document.querySelector("#endturn").style.zIndex = "50";
  document.getElementById("gifhint").style.backgroundImage = "url('src/hints/attack.gif')";
  document.getElementById("texthint").innerText = "Click on an green glowing allied card then click on an enemy to attack.";
  opponentTurn();                       // ← 前面任何一句抛错，这一句永远不执行
});
```

`#endturn` / `#gifhint` / `#texthint` **任一个为 null** → 取 `.style` / `.innerText` 抛 TypeError →
监听器当场中断 → `opponentTurn()` 不执行，而且浏览器**不会重试**，按钮从此"看着有、点着没反应"。
同一行在**加载期**也是同一个毛病（元素还不在就抛 → 整段 `index.js` 中断，它后面定义的函数全不存在）。

**对策（两条，都不改上游）：**

1. **让那几句查得到** —— `游戏/查找.js` 的骨架自愈里加一条：`#gifhint` / `#texthint` 缺了就
   **造两个隐藏空壳**顶着（它们只是装饰性提示条，我们并不显示）。宁可多个空 div，也不要一颗死按钮。
2. **"点了回头看一眼"的安全网** —— 在根上（捕获阶段）盯 `#endturn` 的点击，400ms 后检查：
   `回合留痕.opponentTurn` 涨了、或 `playersTurn` 已变 false → 上游那条路走通了，什么都不做；
   两者都没发生 → 判定链断了，**我们自己把回合推进过去**（调 `opponentTurn`，缺则由兜底接管），
   并往检错层记一条严重，上下文里写清"上游函数在不在、playersTurn 是什么"。

**实测两个方向**（本地独立网页）：

| 场景 | 结果 |
|---|---|
| 正常点一次 | `回合留痕 opponentTurn=1 playerTurn=1`、**安全网记录 0**（不抢戏）、演出 `gain(法力+1)/draw`、自检 47/47 |
| **把 `#gifhint`/`#texhint` 拆掉**（复刻用户问的那种断链）再点 | 安全网记录 **1** 条（`{"安全网":"结束回合的链断了，由我们推进","上游":"function","playersTurn":false}`）、`opponentTurn=1`、演出 `draw/deploy/turn(敌方回合结束)`、自检 47/47 |

## 八、每条规则 ≤ 20000：分片运输（架构不变）

用户 2026-10-05 的要求：**导出后每条正则条目都不超过 20000 字符**（编辑器上限），**总体架构不变**，
把内部功能拆出去、需要时再调用。做到这一步的关键是分清"两种拆法"：

* **真拆功能**（把 `界面.js` 拆成多个独立模块）：它的内部共享上百个**闭包变量**，拆开就得把这些变量
  搬进一个命名空间 —— 伤筋动骨，而且会打散"同一份源码、同一段加载顺序"。**这一步没做**（也不该在没有
  充分理由时做）。
* **数据分片**（本次做的）：把**整份源码当作字符串**分几条规则运进去，最后一条规则把它拼回来
  `(0,eval)` 执行 —— **同一个 IIFE、同一个闭包、加载位置不变**。平台自己就是用 `(0,eval)` 执行规则里的
  脚本的，所以这条路在沙盒里是通的。

```
规则 N    : window.__hsP_界面=window.__hsP_界面||[];window.__hsP_界面.push("<一段源码>");
规则 N+1  : …（同上，另一段）
规则 N+k  : (0,eval)(window.__hsP_界面.join("")); try{ delete window["__hsP_界面"]; }catch(e){}
```

细节与坑：
* 字符串用 `JSON.stringify` 转义（引号/反斜杠安全），并把 `<` 写成 `\u003c` —— 免得平台按 `</script>` 提前截断；
* 每片原始预算 15000 字符（转义后约 15600，包装后 < 17000，稳稳低于 20000）；
* **CSS 不是字符串片，而是按"括号平衡的 `}` 边界"切片**：只在一层花括号收完处断，绝不断进 `@media { … }` 里面
  （断进去那片会整块失效）；每片一个**独立标记**（同一条标记在沙盒里只会生效一次）；
* 载入器执行完把字符串 `delete` 掉（不是置 null）—— 导出本局信息会把 window 上的残留列出来，
  留个 null 键会被误读成"没清干净"。

**结果**：28 条规则，单条最长 **18,616 UTF-16**（门禁 20,000），且总条数远低于硬上限 130。
本地时序夹具复验：骨架齐 ✓ 主页面建起 ✓ 自检 **43/43** ✓ 上游体检 6/6 ✓ 分片键执行后已清空 ✓。

## 九、实机定位到的那几条（2026-10-05：错误条自己报出来的）

装上"可点性探针 + 屏幕错误条"之后，第一次实机就把它俩的价值兑现了 —— 屏幕上直接写着：

```
⚠ 这个页面有问题：展示层/UI_WRONG_SOURCE · 适配/宿主/SKELETON_INCOMPLETE · 点不到：返回原生界面 ← 被 hs-table 盖住
```

三条逐一查清：

1. **`点不到：返回原生界面 ← 被 hs-table 盖住`** —— **真因**：`#hs-backbar`（适配层创建的返回条）
   在样式里**根本没有规则**，是**静态定位**；而 `#hs-table` 是绝对定位的整屏图层。
   静态元素永远压不过定位元素，所以按钮被牌桌盖住、点不到。
   修法：给 `#hs-backbar` 定位 + `z-index:40`（按钮 41），抬到牌桌之上。
2. **`SKELETON_INCOMPLETE` 误报** —— 检错层那条不变量还在用 `document.getElementById`（被平台改写过的
   方法），真机上拿不到舞台里的元素 → 误判"骨架缺"。修法：与界面同一口径，改走 `HS_UI_找`（根部作用域）。
   （我先前只改了「本局信息」里那一行，漏了这条断言 —— 同一个坑踩两次，所以这里记下来。）

## 十、源码与卡必须"对得上"：新增 `建沙盒卡.py --check`

用户转来的一条建议，一针见血：

> 你做了检错、状态、界面三个模块，源码更新了，但 **JSON 里还是旧版** —— 相当于测试和交付没对上。
> 那个旧的状态模块在单位掉血时还会往不存在的路径写数据，直接抛一些奇怪的异常。

两件事都成立，而且互为因果：

1. **卡里的 JS 是构建期"内联"进去的**。改了源码不重打包，卡里就还是旧代码；而两边看起来都正常
   （旧卡也有界面、也能发牌），于是"我这边测的是新代码、他那边跑的是旧卡"能拖很久。
   早期证据就摆在报告里：那份导出 `总数 40`，而当时的自检清单已经是 46/48 —— 它跑的确实是旧卡。
2. **他说的那个"往不存在的路径写"** 正是 `状态.js` 的旧缺陷：权威状态里 `场上` 是**对象数组**、
   没有 `单位` 映射，而 `求差/应用` 是按**引擎那套形状**写的（`压入/抽出` 拿 id、字段变化写成
   `置 ['单位', id]`）→ 掉血那一拍就会去写一个**不存在的路径**，重放对不上、抛怪异常。
   修法见 `说明/16` 第五节：**把权威状态形状对齐引擎**（`单位` 映射 + `场上: [id]`），
   并给 `应用` 加上"路径中间不存在就建出来"的兜底；机器断言在 `test_状态.mjs`（58 项）。
   刚复验过：掉血那一拍现在是 `置 ['单位','u1']`（路径存在）、**重放与新状态逐字段一致**、提交零问题、对账为空。

**闸门**：`python 建沙盒卡.py --check` —— 读卡里的 `HS_BUILD`（构建戳）与**当前源码**的哈希比：

```
[校验卡] ✓ 源码与卡一致（构建戳 79710fa2）
[校验卡] ✗ 卡过期：卡里 79710fa2，当前源码 82ac9625
          → 跑 python 建沙盒卡.py 重新打包，再重新导入
```

两个方向都实测过（改源码不重打包 → 红；恢复 → 绿）。它现在是 `打包展示.py` 的**第四道闸门** ——
随包的卡一旦与源码不一致，打包直接失败、不许发布。
