# 分层与已修问题（长期参考）

> 两份意图：**① 把"引擎 / 动画 / 卡的特殊效果"分开管理**（用户 2026-10-03 的指令，也是那篇 Phaser 卡牌文的核心建议）；
> **② 把踩过的坑逐条存档**，避免同一个坑第三次踩。

---

## 一、三层分离（目标结构）

那篇文章把卡牌游戏拆成三块，我们照这个来分，**改动时不许互相穿透**：

| 层 | 回答什么 | 归谁 | 不许做什么 |
|---|---|---|---|
| **① 基本引擎**（规则） | 这一回合**能**发生什么、结果是多少 | 上游原代码 + 我们的规划器（`界面.js` 里的 `planEnemyTurn`/`applyExchange`） | **不许碰 DOM 样式、不许画东西**。结算只写"数值"（血量文本、加/删卡） |
| **② 动画（演出）** | 这些结果**看起来**怎么发生 | `演出.js`（锁 / 队列 / 六个原语 / 配方表 / `whenIdle`） | **不许改规则**。只播、只在自己那一拍调用 `onStrike` 去施加引擎给的变更 |
| **③ 卡的特殊效果** | 单张卡**自己**做什么 | **待建：`card-effects.js`**（一张按卡名索引的效果表 + 一个执行器） | 不许直接写 DOM；产出"动作"交给 ① 结算、交给 ② 播 |

**现在的状态**：①②已经分开了（引擎在 `界面.js`、演出在 `演出.js`），
③还散在上游的 `card_effects.js` 里（按卡名硬编码、直接改 DOM）——**效果表是下一件要做的**，
做完之后 ③ 就有了明确的落点，也才好"加卡只动效果表"。

**为什么必须分**：一旦效果直接改 DOM（上游现状），动画层就失去了"变更清单"，
只能事后回放；反过来动画层一改规则，加速/跳过/切后台就会丢结算。
分层之后才有：**先算完 → 按队列播 → 每一条在自己的那一拍施加**。

## 二、已修问题存档（每条都记清"症状 / 根因 / 改法"）

### 1. 神圣护盾不生效（2026-10-03）
- **症状**：有护盾的单位护盾没用，那次攻击也像"没发生"。
- **根因**：上游所有护盾/嘲讽处理都要读 `children[2]`
  （`currentAttackerElement.children[2].classList.add('divineShieldBreak')`），
  而**场上的卡只有 2 个子节点**（两个攻血徽章）→ `children[2]` 是 undefined →
  **抛 TypeError** → 它后面的扣血整段不执行。
- **改法**：`assignNew` 里给每张上场卡**补一个空 `<div>` 当第三子节点**
  （护盾遮罩图本来就被剥了，空 div 正好占位）。

### 2. 3 点攻击打出 4 点伤害 / 又能连打（2026-10-03）
- **症状**：攻击伤害比攻击力多；同一个单位一回合能攻击好几次。
- **根因**：上游 `attack()` 每次都
  `document.querySelectorAll('.cardinplay').forEach(e => e.addEventListener('mousedown',…))`，
  而它**每个我方回合都被调用一次** → 监听器**累积**，回合越往后同一次攻击被处理的次数越多。
- **改法**：把 `attack()` 包成**幂等**（只绑一次）；之后每回合只手工补 `canAttack`/绿光，
  **而且只在我方回合开始那一拍补**（补早了会把"已经打过"的单位又刷成可攻击 → 连打）。

### 3. 「落地:false」的假警报（2026-10-03）
- **症状**：导出里老是显示攻击"没落地"，但伤害其实生效了。
- **根因**：诊断用的 `healthSnapshot()` 取血量写的是 `children[1].children[0]`，
  而**两个英雄结构不同**（我方 `#playerhero` 少一层）→ 我方英雄**根本不在快照里**。
- **改法**：统一走 `heroNode()`；并给导出补上 `实扣血`（和`攻方攻击力`并排，
  一眼看出是不是倍数关系）。

### 4. 满员还上场 → 卡片挤在第 1 格（2026-10-03）
- **症状**：5 格已满还继续上场，多出来的卡全挤在第 1 格。
- **根因**：`assignNew` 找不到空格时**直接 return** → 那张卡没有 `left` → 停在棋盘左缘
  （= 第 1 格的位置）。
- **改法**：**所有登场途径的唯一入口** `assignNew` 加硬闸：没空格就把这张卡收掉，
  给一声「战场已满」提示，并打标记**不演退场动画**。

### 5. 召唤类卡牌的效果被玩家操作挤掉（2026-10-03）
- **根因**：上游是"先把卡 append 进 DOM、再在 `setTimeout` 里算效果"，
  玩家能在效果结算前把格子填满。
- **改法**：出牌后**锁住输入 800ms**，让上游那批定时器把效果跑完；
  外加第 4 条那道硬闸兜底（锁只把窗口关小，闸才是保底）。

### 6. 自检在自己环境里误报（2026-10-03）
- **症状**：`HS_INTERACT.check()` 在用户沙盒里报"预览换边规则不存在 / 蒙版 .on 不显示"，
  而样式其实是好的。
- **根因**：那几条是**扫 `document.styleSheets` 找规则文本**实现的；
  沙盒对 `styleSheets/cssRules` 的访问受限，扫不到。
- **改法**：一律改成**行为检查**（把类加上去 → 读计算值 → 还原），与环境无关。
- **教训**：**诊断本身也会骗人**。所以每加一条诊断都尽量让它**自带原因**
  （`落地` 现在带攻方/攻击力/实扣/目标还在/currentAttacker），而不是只给个布尔值。

### 7. 敌方单位可以重复上场（2026-10-02，已修）
- 规划器出错时**退回上游 `opponentTurn`**；上场前先数格子（`occupied < 5`）。

## 三、改动时的铁律（每次改完都要过一遍）

1. **上游一字未改** —— 只包装、旁听、拦截（构建校验里有断言盯着）。
2. **结算不许先于动画** —— 规划只看不碰，每一条在它自己那一拍才施加。
3. **"所有演出播完"只有一个时点** —— `HS_PIPELINE.whenIdle()`（队列空 + 没在跑）。
4. **凡是能被订阅的东西都要有确切来源** —— 宁可用上游自己的信号（`playerTurn` 被调用 = 敌方回合结束），也不要靠猜。
5. **凡是"我们主动制造的事件"必须能被识别**（`__hsStrike`），否则会被自己的锁吃掉。
6. **凡是 `catch` 至少留一行输出** —— 静默失败已经坑过三次。
7. **每次改完**：`node --check` 两个脚本 → `python 工具/组装.py` → 两个单测 → 刷新页面跑 `HS_INTERACT.check()`。
