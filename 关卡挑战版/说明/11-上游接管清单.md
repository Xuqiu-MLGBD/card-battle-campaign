# 上游接管清单（逐文件处置 + 阶段顺序 + 删除门槛）

> **这份文件是"删掉上游"的前置依据。** 用户 2026-10-03 的要求：
> 「把所有上游中有用的代码取出，写成自己的版本，然后删除上游所有文件，统一所有代码的内容各要素各类全是自己的命名。」
>
> **先说结论：这件事现在还不能一步做完，删早了游戏当场就死。** 上游一共 **8617 行 / 17 个文件**，
> 而我们仍然依赖它做四件核心的事：**卡面 DOM 的生成**、**资源与回合的推进**（法力/抽牌/出牌/胜负）、
> **卡的特殊效果**、以及**整套布局样式**（`styles.css` 3297 行）。
> 所以这份清单把"接管"拆成 **7 个阶段**，每个阶段都有自己的落点与验收；
> **删上游放在最后一个阶段**，并且给出"什么时候才允许删"的硬门槛。
>
> 关于"命名统一"：本仓库的词汇已经统一到我们自己的一套（攻耗/恢复/反击/体力/席位/堆叠/待选择/投影…），
> 接管的每一块都必须落进这套词里，且**不新增上游术语**（见 §四的对照表）。

`组装.py` 把它们那几行注释掉）。摘之前每个都查过"整个运行时零引用"：`requestAnimFrame` 只有 `fps.js`
自己用；开包 / 雪花 / 时钟 / 测试函数的引用**全 0**；`window_focus` 只切 `body.className`，剥美术后无人依赖。
另外把 `load.js` 唯一还有用的两件事接管进 `外壳.js`：开场把 `#contents` 藏起来（`hideContentsAtFirst`）、
以及**替玩家点掉门槛时不再要求它可见**（原来要等 `load.js` 把它亮出来才点，摘掉之后没人亮它，
于是那句永远 return → 整局进不去，实测踩到）。

> ⚠⚠ **这一批最值钱的教训（比省下的 1211 行重要）**：摘一个上游文件之前，除了查"**谁调用它的函数**"，
> 还必须查"**它当年往 window 上挂过哪些全局量**" —— 因为**别的上游文件会裸读那些名字**。
> 实测踩到：`load.js` 定义过 `mainmenuOST`、`crowdSnd`、`createPack`（以及
> `hasPlayedTutorial_deserailized`），而 `elementsController.js` **到处**在读它们
> （菜单音乐的淡出/暂停、商店买包的收尾、门槛的分支判断）。少一个就是 **ReferenceError**，
> 而它发生在**事件处理器里**：门槛 onclick 一抛，流程静默中断 —— 我们排在它后面的
> `setTimeout(enterFight, 300)` **再也执行不到**，整局进不去。
> 症状很误导人：血量/法力读出来是空、`#contents` 一直 hidden，但"哨兵"却被置上了（因为哨兵写在
> 抛错点**之前**），看着像"已经走到了"。
> 修法照 `strip.js` 的老办法 —— **把能力垫上、不改调用点**：`外壳.js` 新增 `stubSilentGlobals()`，
> 用静音 `Audio` 空壳与空函数补齐那些名字，并在**加载期**执行（上游解析时就可能读）。
> 位置也有讲究：必须排在 `W.Audio = SilentMedia` **之后**（要用新 Audio 造空壳）——
> 放早了在桩 DOM 里直接抛（测试当场红）。

6. 备份里留一份"上游还在"的快照（现在每轮都有，天然满足）。

## 五、第二轮接管：卡数据 + 卡面工厂（2026-10-03，已做）

用户的要求是「直接把上游有用的内容取出，改成自己的统一整理编排」。这一轮取的是**上游最大的
"内容"来源** —— `deck.js` 那 287 行，它干两件事（定义卡、造卡的 DOM），**两件都拿回来了**：

| 取什么 | 怎么取 | 落在哪 |
|---|---|---|
| **37 张卡的数据**（费/攻/血/稀有/说明） | `抽上游卡数据.py` **机械抽出**（正则读 `new MinionCard(…)` 那 37 行），不手抄 | `游戏/卡库.js` **丙段**的卡表 |
| 效果（战吼/亡语/关键词）与体力（攻耗/恢复） | 我们自己的那套（丙段 + 下面的 `体力规则`）—— 上游只把它写在卡面文案里 | 同上 |
| **卡面 DOM 工厂** | 自己写：`造场上卡` / `造手牌卡`（层级照上游位置，类名是我们的） | `游戏/卡库.js` **丁段** |
| 牌库与发牌 | 自己写 `牌库`（挂成 `window.Deck`）+ `freshDeck`（**自由对战卡池照上游返回顺序**的 63 张位） | 丁段 |
| 去卡图 | **不再需要**：我们造的卡本来就没有 `imageString` —— 从"运行时包一层"变成"由构造保证" | `外壳.js` 里那段包装已删 |

**过渡契约**（只在 `index.js` 还被上游驱动时有效，阶段 C 之后删）：
- 上游按 `children[i]` 读攻/血/费用/文案/名字（例如给手牌染色读 `children[0].children[4]`）→ **层级位置保持原样**，
  但同一批节点上加了**我们自己的类名**（`hs-atk`/`hs-hp`/`hs-mana`/`hs-info`/`hs-name`/`hs-border`），
  我们的代码只认自己的类名；
- 上游 `startGame()` 里写 `new Deck(cards)`、读卡对象的 `.name/.mana/.attack/.health/.info/.imageString`
  → 我们的卡对象**两套名字都给**。

**关键数字（实测）**：
- 页面**一次都不请求 `deck.js`**；`window.Deck.name === '牌库'`；`HS_CARDS` 37 张；
  手牌结构与类名都是我们的（`.hs-name` = `Elven Archer` 等）；
- 出牌→攻击实测通过（Elven Archer 1/1 打 Boulderfist Ogre 7→6，自己因攻耗 1 当场消失）；
- 断言：**451 项**（212 + 99 + 108 + 32）+ 页面自检 **28/28**，`组装.py --check` 通过；
- 进卡体量随之变化：**484,573 UTF-16 / 17 条规则**（把 deck.js 从模块清单里去掉之后的实测）。

**顺带消掉的三条老约束**（都写进了对应文件）：
1. 「甲段必须赶在别人覆盖 `freshDeck` 之前抓一份上游的」—— 数据是我们自己的表，没有这个先后依赖了；
2. 「`外壳.js` 必须排在 `levels.js` 抓 `freshDeck` 之前」—— 同一条，消失；
3. 「`test_campaign.mjs` 要守『卡库必须抓到被包装过的 freshDeck』」—— 换成新的不变量：
   **卡表自带全量 37 张、牌组用到的名字一个不缺、每张卡都带卡面工厂**。

## 六、第三轮接管：卡的效果（2026-10-03，阶段 D，已做）

这一块是**最后一片"两套规则"**：引擎里有效果表，页面上出牌却还在用上游
`card_effects.js` 那 326 行直接改 DOM。用户说"继续"，就把它收回来。

**上游那份长什么样**（为什么非收不可）：`cardPlaceSnds()` 是一个**按卡名 if-else** 的大函数
（22 张卡各一个分支），由 `index.js` 的 `placeCardFunc` 在牌落场后同步调一次，靠全局量
`getNameOfElement` 认出刚打的是哪张卡。三个问题：
① 效果是**写死的 DOM 操作** —— 加一张卡要改代码（这就是"直接改 DOM"的反面教材）；
② **一堆分支其实只播了个音效** —— Elven Archer / Voodoo Doctor / Glacial Shard 这些
  "要选目标"的战吼，上游的真效果**根本没做**；
③ 口径与引擎不一致（Stormwind Champion 上游是"其他随从全体 +1/+1"，我们表里是"一个友方随从"）。

**我们这一版**（都在 `界面.js`，与 `应用一次攻击` 并列）：

| 件 | 干什么 |
|---|---|
| `应用战吼(卡名, 席位, 来源)` | 读**同一张效果表**（`卡库.js` 丙段的 `战吼`），逐条决定目标并执行 |
| `执行效果(效果, 席位, 目标El)` | 落到 DOM：伤害 / 治疗 / 加成 / 召唤 / 抽牌 / 冻结 / 消灭 —— **与引擎同一套词汇** |
| `效果可选(席位, 口径)` | 目标口径 → 这一刻能选哪些元素（与引擎的 `可选目标()` 一一对应） |
| **待选目标模式** | 要玩家选的效果：合法目标**描边** + 提示，点一个才生效；Esc / 右键 = 落空。这就是引擎 `待选择` 的界面版 —— **不替玩家猜目标**（只有一个合法解时自动绑，那不是猜） |
| `召唤随从` / `抽一张` | 战吼召唤与抽牌（自己造卡落格；玩家侧走上游那份牌库、敌方侧走我们的 `enemyHand`） |
| **`触发亡语`** | 挂在 `应用一次攻击` 的**移除那一拍**上 —— 所以"谁死了 → 谁的亡语"只有一处判断 |
| `接管出牌效果()` | **把 `cardPlaceSnds` 换成我们的**（`index.js` 那句调用一个字不动）—— 老规矩"改能力，不改调用点" |

**顺带堵掉了《全线排查》里那条 ❌**：「敌方打出带效果的牌时，效果算谁的？」
—— 上游那条路只认玩家的 `getNameOfElement`，**敌方出牌从不走效果**。
现在两边同一个执行器、同一张表：`playFromEnemyHand` 落场之后调一次 `应用战吼(卡名, 'enemy', el)`。

**实测（浏览器，逐条）**：

| 用例 | 结果 |
|---|---|
| **召唤** | Razorfen Hunter 上场 → 场上多出 **Boar** ✓ |

| **亡语** | 打死 Sludge Belcher → 场上留下 **Slime** ✓ |

## 九、第四轮：用户报的"按不出卡 + 疯狂提示目标"（2026-10-03）

用户的原话是「你乱搞了什么，为什么按不出卡，旁边疯狂提示目标（ESC）」。这一段记**根因**，
因为它是阶段 D 那次接管的直接后果，教训是通用的。

**两个成因，都不是拖拽坏了**：

1. **敌方战吼在问玩家选目标**。`应用战吼(卡名, 席位, 来源)` 第一版不分席位，只要效果要选目标
   就进"待选"——第一关敌方牌组里就有 Elven Archer / Voodoo Doctor，于是**敌方的战吼挂在玩家头上**，
   玩家既不知道在给谁选，也没法取消。
   改法：待选只对 `席位 === 'player'` 开；非玩家席位走 `机器人选目标(效, 席位, 可选)`
   （伤害类指对面、加成类指自己），**敌方出牌不再打扰玩家**。
2. **提示把输入锁住了**。`进入待选` 最早用 `notice()`，而它走演出管线的 `present()` → 锁输入约 1 秒；
   这 1 秒里点手牌会被静默吞掉，玩家就"按不出卡"，而且每点一次再提示一次，看起来像"疯狂刷提示"。
   改法：提示换成**不锁输入**的常驻条 `#hs-pick`（`提示条()`，`pointer-events:none`）。

**顺带立了一条硬规矩**（写在 `onDown` 那段注释里）：**待选绝不能变成模态** ——
玩家开始任何新操作（点手牌 / 点自己单位 / 结束回合）就 `放弃待选('你做了别的操作')`，
那条战吼落空并说一声；选择被放弃是明确的、有反馈的，而不是"点了没反应"。

**另外两条同期查出来的真 bug**（用户没报，验的时候撞见）：

- **关卡牌组根本没发到手上**（`卡库.js` 里 `freshDeck` 有两个写入点：乙段设关卡牌组、丁段设自由卡池，
  丁段在后面 → 整条覆盖）。于是 `?level=1` 也在发 Lich King / Deathwing，第一关难度形同虚设。
  现在乙段只**登记** `HS_LEVEL_DECK`，丁段的 `freshDeck` 是**唯一写入点**并在里面优先取关卡牌组。
  → 一般化的教训：**一个量只许有一个写入点**，别的模块只许"登记来源"。
- **场上卡没有名字**：上游是拿**卡图**认人的，卡图剥掉之后场上随从只剩几个数字
  （实测 `1 1 -1 +1`）。`造场上卡` 现在追加 `children[3] = .hs-board-name` —— 追加在最后，
  不动上游读的 `children[0]/[1]`，也不动手牌那条 `children[0].children[5]`。

**这一轮的复验**：`组装.py --check` 五项全绿 · 四套 node 断言 **451 项 0 失败**（回归基线两个哈希未变）·
页面自检 **29/29** · 浏览器端到端（拖牌落场付法力 → 我方战吼待选 → 点"结束回合"待选让路并推进回合 →

**顺带踩到的坑（记下来）**：
1. 上游 `startGame()` 会拿 `.opposingHeroHealth == 10` 嗅探"是不是教程"，

2. **动布局就会碰到几何基准**。把部署位改成"按 1..5 格居中"之后，卡片的落点立刻偏了：

   —— 格子一居中，"第 0 格"就不再是 0，于是整排卡少算一个居中边距（5 格偏 45px、1 格偏 444px）。
